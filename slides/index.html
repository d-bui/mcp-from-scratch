FastAPI で
シンプルな MCP サーバーを作る

読む① データとログイン 読む② 受付と門番 読む③ ふつうの CRUD 読む④ 合鍵と MCP 化 読む⑤ 動かしてつなぐ
発表者：ミズン
なぜ作る？

アプリを覚えるより、AI に話す方が早い

  • 今はもう、アプリを操作するより AI とチャットしている時間の方が長い
  • アプリは使い方を覚える必要がある（画面・メニュー・手順書）— チャットなら不要
  • その画面（フロントエンド）を作るのも、AI に手伝わせてもけっこう大変
  • → 機能は API で作り、MCP でつなげば「話せるアプリ」になる

例: 管理画面。API は AI がすぐ書けるので、MCP で包めば画面ができる前からビジネスチームが会話で管理を始められる（エンジニアの DB 直叩きも不要。権限チェックは API を必ず通るので安全）。

はじめに

MCP サーバー = AI に渡す「道具箱」＋「説明書」

  • 道具（ツール）1 つ = AI にさせたいこと 1 つ
    名前・説明文・入力の形が付いていて、AI は説明文を読んで使い方を決める
  • 道具を渡していない操作は、AI はそもそもできない（今日もここが軸）
一覧を見る list_users 1 人を見る get_user 追加する create_user

今日の道具箱はこの 3 つ（削除の道具はわざと入れない）。これが main.py 1 ファイルにできているので、上から読んでいく。

全体の地図

main.py は 5 つのブロック ― 役割で見る

前半 ― ふつうの Web アプリ
読む① データと人間のログイン デモデータと、ログイン → セッショントークン（いつもの Web と同じ）
読む② 受付と門番 入口で「人間か AI か」を見分け、危ない操作は人間専用にする
読む③ ふつうの CRUD ただの FastAPI エンドポイント（docstring があとで効く）
後半 ― ここから AI のための追加
読む④ AI の合鍵と MCP 化 合鍵 1 行 + リストに書いた操作だけ AI の道具になる
読む⑤ 動かしてつなぐ python main.py で起動 → AI は URL（/mcp）につなぐだけ

AI のための追加はファイル後半にまとまっている。前半だけなら、ただの「ログインつき Web アプリ」として動く。この順に上から読む。

読む①② ふつうの Web アプリ ― ログインと受付

前半は、ただの「ログインつき Web アプリ」

main.py ― ログインと受付
LOGIN_USERS = {"alice": "demo"}      # 人間: ログインして入館証をもらう
sessions: dict[str, str] = {}

@app.post("/login", operation_id="login")
def login(body: LoginBody):
    """ログイン。成功するとセッショントークンを返す（人間の入口）。"""
    ...
    token = "usr_" + secrets.token_hex(16)

def get_actor(authorization: str | None = Header(None)) -> dict:
    """Bearer トークンを見て「人間か AI か」を確定する（入口は 1 箇所）。"""
    if token in sessions:   return {"type": "user", ...}  # 入館証？→人間
    if token in AGENT_KEYS: return {"type": "agent"}      # 合鍵？→AI（定義は読む④）
    raise HTTPException(401, "有効なトークンがありません")

def user_only(actor: dict = Depends(get_actor)) -> dict:
    """門番: 破壊的操作に付ける。AI の合鍵なら 403。"""

トークン発行も 401 も、いつもの Web と同じ作り。唯一の伏線は、受付が「AI の合鍵」も見ること（鍵そのものは読む④で登場）。削除には Depends(user_only) を付けるだけ。なお AI 側の認証は、合鍵（PAT）の代わりに OAuth を使う設計もある（リモート公開の本格運用向け）。

読む③ ふつうの CRUD

ここまでは AI と無関係の、ふつうの API

main.py ― CRUD
@app.get("/users", operation_id="list_users")
def list_users(actor: dict = Depends(get_actor)):
    """全ユーザーの一覧（id・名前・email）を返す。ID が必要な操作の前にまずこれで確認する。"""
    return {"users": users}

@app.post("/users", operation_id="create_user")
def create_user(body: UserBody, actor: dict = Depends(get_actor)):
    """ユーザーを追加し、追加したユーザーを返す。"""
    user = {"id": ..., **body.model_dump()}
    users.append(user)
    return {"user": user}

operation_id があとで道具の名前に、ハイライトの docstring が説明文になる（読む④）。それ以外はただの FastAPI。

読む④ ここから AI のための追加（今日いちばん大事）

合鍵 1 行 + リスト数行で、AI の道具箱になる

main.py ― AI のための追加
AGENT_KEYS = {"agent-demo-key"}   # AI 用の合鍵（PAT）— 追加はここから

mcp = FastApiMCP(
    app,
    name="Users MCP",
    include_operations=[
        "list_users", "get_user", "create_user",
        # delete_user と login はわざと書かない = AI から見えない道具
    ],
    auth_config=AuthConfig(dependencies=[Depends(get_actor)]),  # /mcp 自体にも合鍵
)
mcp.mount_http()   # → http://localhost:8000/mcp

結果: 一覧・取得・追加は人間も AI も OK、削除は人間だけ（AI は道具が無く断り、REST を直接叩いても門番が 403 — 二段構え）。「この辺は全部 OK」とざっくり開けると開けたくないものまで開く事故が起きる（実体験）。

読む④ のたね明かし

説明文は書かない ― docstring がそのまま説明文になる

書いたもの → fastapi-mcp が作るもの
# main.py に書いたのはこれだけ:
@app.get("/users/{id}", operation_id="get_user")
def get_user(id: int, actor: dict = Depends(get_actor)):
    """ユーザーを 1 人返す。id は list_users で確認した実在の ID を使う（推測しない）。"""

# ↓ AI にはこう見える（自動生成された道具）:
#   name:        get_user
#   description: ユーザーを 1 人返す。id は list_users で確認した
#                実在の ID を使う（推測しない）。
#   input:       { id: integer }   ← 型ヒントから自動

自分で書くのは docstring だけ。そこに「AI へのお願い」（推測しない・先に一覧を見る）を書き込むのがコツ — AI の動きはコードより言葉で決まる。

読む⑤ 動かしてつなぐ

起動したら、AI は「つなぐだけ」

  • 裏方: python main.py で起動（ポートは 8000 固定。ターミナルはここだけ）
  • Claude Code / Cursor: 設定に URL + 合鍵を書くだけ（同梱の .mcp.json.example をコピー。手順は付録②）
  • 会話:「ユーザー一覧見せて」→ list_users ／「登録して」→ create_user
  • 「1 番を削除して」→ 道具が無いので断られる（見せ場）

MCP はオープン規格なので、Claude 以外の AI クライアントからも同じ URL につなげる。ローカルで配って使いたい場合（Claude Desktop など）は .mcpb に詰める方法がある — 付録③。

まとめ

入口は分ける・許可はリストで・説明は文章で

  • main.py を上から読めば、MCP サーバーの作り方はぜんぶ分かる
  • ふつうの API に、AI 対応は後付けできる — 既存システムにも同じ手順
  • AI の動きは説明文（docstring）が決める — コードより言葉が効く
  • コード: github.com/d-bui/mcp-from-scratch ／ この後ろに付録（手順書）3 枚
  • 質問どうぞ！

参考: MCP 自体はオープン規格（modelcontextprotocol.io）で、ChatGPT / Cursor / Gemini など他の AI クライアントからも同じサーバーにつなげる。

付録① 手順書 ― サーバーを動かす

クローンして起動するまで ― 3 分

ターミナル
$ git clone https://github.com/d-bui/mcp-from-scratch
$ cd mcp-from-scratch
$ python3 -m venv venv
$ ./venv/bin/pip install -r requirements.txt
$ ./venv/bin/python main.py
# → ポートは 8000 固定。MCP エンドポイント: http://localhost:8000/mcp
# デモの人間ユーザー: alice / demo ／ AI 用の合鍵: agent-demo-key

動作確認は README の curl 例で。人間トークンで削除が 200、AI の合鍵で削除が 403 になれば正常。

付録② 手順書 ― AI クライアントからつなぐ

つなぎ方 3 通り ― どれか 1 つでいい

Claude Desktop ― コマンド不要
1. dist/users-mcp-local.mcpb をダブルクリック
2. フォームに URL（既定のまま）と合鍵 agent-demo-key を入力 → 完了
Claude Code ― .mcp.json を置くだけ（URL + 合鍵を書いた設定ファイル）
$ cp .mcp.json.example .mcp.json   # 同梱の例をコピー
$ claude                           # フォルダで開くと自動検出 → 初回に承認 → /mcp でツール一覧
Cursor ― .cursor/mcp.json に書くだけ
{ "mcpServers": { "users": { "url": "http://localhost:8000/mcp",
    "headers": { "Authorization": "Bearer agent-demo-key" } } } }

つないだら「ユーザー一覧見せて」で動作確認。「1 番を削除して」と頼むと断られるのが正しい挙動。

付録③ 手順書 ― 配布用 .mcpb を作る

.mcpb は 2 コマンドで作れる

ターミナル
$ cd mcpb && npm install
$ npx @anthropic-ai/mcpb pack . ../dist/users-mcp-local.mcpb
# 中身: manifest.json + mcp-remote（stdio → HTTP の橋渡し）だけ
# HTTP 型の MCP はそのまま .mcpb に入らないため、橋渡しを詰めている

受け取った人の手順は「ダブルクリック → フォームに URL と合鍵」だけ（付録②）。合鍵は OS の安全な場所に保存される。詳しい仕組みは README と manifest.json を参照。
