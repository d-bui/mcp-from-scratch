MCP サーバーを作る
― FastAPI で 1 ファイル、5 つの部品を組み立てる

① 土台の API ② 入口（受付） ③ やっていいことリスト ④ AI への説明係（自動） ⑤ つなぎ方
発表者：ミズン ／ コードは GitHub で共有します
はじめに

MCP サーバー = AI に渡す「道具箱」＋「説明書」

  • 道具（ツール）1 つ = AI にさせたいこと 1 つ
    名前・説明文・入力の形が付いていて、AI は説明文を読んで使い方を決める
  • 道具を渡していない操作は、AI はそもそもできない（今日もここが軸）
一覧を見る list_employees 1 人を見る get_employee 追加する create_employee

今日の道具箱はこの 3 つ（削除の道具はわざと入れない）。これを FastAPI + fastapi-mcp で、main.py 1 ファイル（約 130 行）に作る。

全体像

入口は 2 つ、中身は 1 つ ― 同じサーバーを人間と AI が使う

人間
ログインして入館証（トークン）をもらう
AI（Claude）
合鍵を持って URL（/mcp）につなぐ
⟶⟶
受付 来たのが人間か AI かをここで見分ける
やっていいことリスト AI の道具箱に入れる操作はここに書いたものだけ
API 本体 ふつうの CRUD（FastAPI）
AI への説明係 fastapi-mcp が自動生成。/mcp で待っている

AI が道具を 1 つ使うたび、お願いが 1 回右の中身へ飛ぶ。これを「土台 → 入口 → リスト → 説明係 → つなぎ方」の順に作っていく。

完成マップ

main.py の地図 ― 部品 5 つ、全部 1 ファイル

部品main.py の場所やること（一言で）
①@app.get("/employees") などふつうの CRUD（お願いを受けて返す）
②login() + sessions人間の入口: ログイン → 入館証を発行
②AGENT_KEYS + get_actor()AI の入口: 合鍵を確認して「誰が来たか」を確定
②user_only()門番: 破壊的操作を人間専用にする
③include_operations=[...]AI の道具箱に入れる操作を選ぶ
④FastApiMCP(app, ...)docstring から道具＋説明文を自動生成
⑤/mcp（+ 任意で mcpb/）ローカル URL でつなぐ

部品を分けて書いておくと、「AI まわりを変えたい」ときにどこを触ればいいかがすぐ分かる。

作るもの① まず、ふつうの API

土台を作る ― ただの FastAPI エンドポイント

main.py ― ① 土台
@app.get("/employees", operation_id="list_employees")
def list_employees(actor: dict = Depends(get_actor)):
    """全社員の一覧（id・名前・給与）を返す。ID が必要な操作の前にまずこれで確認する。"""
    return {"employees": employees}

@app.post("/employees", operation_id="create_employee")
def create_employee(body: EmployeeBody, actor: dict = Depends(get_actor)):
    """社員を給与つきで追加し、追加した社員を返す。"""
    emp = {"id": ..., **body.model_dump()}
    employees.append(emp)
    return {"employee": emp}

ここまでは AI と無関係の、ふつうの Web API。ハイライトの docstring があとで効いてくる（④ で AI への説明文になる）。operation_id が道具の名前になる。

作るもの② 入口（受付） ― 人間側

人間の入口 ― ログインして入館証をもらう

main.py ― ② 受付（人間）
LOGIN_USERS = {"alice": "demo"}   # デモ用の固定ユーザー
sessions: dict[str, str] = {}      # 入館証 → だれか

@app.post("/login", operation_id="login")
def login(body: LoginBody):
    """ログイン。成功するとセッショントークンを返す（人間の入口）。"""
    if LOGIN_USERS.get(body.login_id) != body.password:
        raise HTTPException(401, "login_id か password が違います")
    token = "usr_" + secrets.token_hex(16)
    sessions[token] = body.login_id
    return {"token": token}

いつもの Web サービスと同じ流れ。勉強用に一番シンプルな形（本番では Cookie などにする）。

作るもの② 入口（受付） ― AI 側と門番

AI は合鍵で入る。入口で見分けて、門番が守る

main.py ― ② 受付（AI）
AGENT_KEYS = {"agent-demo-key"}  # AI 用の合鍵（実務では DB にハッシュ保存して発行・失効を管理）

def get_actor(authorization: str | None = Header(None)) -> dict:
    """Bearer トークンを見て「人間か AI か」を確定する（入口は 1 箇所）。"""
    token = (authorization or "").removeprefix("Bearer ").strip()
    if token in sessions:   return {"type": "user", ...}  # ① 入館証？→人間
    if token in AGENT_KEYS: return {"type": "agent"}      # ② 合鍵？→AI
    raise HTTPException(401, "有効なトークンがありません")

def user_only(actor: dict = Depends(get_actor)) -> dict:
    """門番: 破壊的操作に付ける。AI の合鍵なら 403。"""
    if actor["type"] != "user":
        raise HTTPException(403, "この操作は人間ユーザー専用です")

入口を分けておくと「AI の鍵だけ止める・記録する」が簡単。削除エンドポイントには Depends(user_only) を付けるだけ。

作るもの③ やっていいことリスト（今日いちばん大事）

AI の道具箱に入れる操作は「リストに書いたものだけ」

main.py ― ③ リスト + ④ 説明係の起動
mcp = FastApiMCP(
    app,
    name="Employee MCP",
    include_operations=[
        "list_employees", "get_employee", "create_employee",
        # delete_employee と login はわざと書かない = AI から見えない道具
    ],
    auth_config=AuthConfig(dependencies=[Depends(get_actor)]),  # /mcp 自体にも合鍵
)
mcp.mount_http()   # → http://localhost:8000/mcp

「この辺は全部 OK」とざっくり開けると開けたくないものまで開く事故が起きる（実体験）。削除は「リスト外（見えない）」+「門番で 403」の二段構え。

作るもの③ ができると

同じ API でも、できることが違う

操作人間AI
ログイン✔（入口）―
社員一覧を見る✔✔ リストにある
社員を 1 人見る✔✔ リストにある
社員を追加する✔✔ リストにある
社員を削除する✔✘ 見えない + 門番 403
/mcp につなぐ―✔ 合鍵必須

AI に「2 番を削除して」と頼んでも、道具箱に削除が無いので断ってくる。仮に REST を直接叩かれても門番が 403。

作るもの④ AI への説明係（自動生成）

説明文は書かない ― docstring がそのまま説明文になる

書いたもの → fastapi-mcp が作るもの
# main.py に書いたのはこれだけ:
@app.get("/employees/{id}", operation_id="get_employee")
def get_employee(id: int, actor: dict = Depends(get_actor)):
    """社員を 1 人返す。id は list_employees で確認した実在の ID を使う（推測しない）。"""

# ↓ AI にはこう見える（自動生成された道具）:
#   name:        get_employee
#   description: 社員を 1 人返す。id は list_employees で確認した
#                実在の ID を使う（推測しない）。
#   input:       { id: integer }   ← 型ヒントから自動

自分で書くのは docstring だけ。そこに「AI へのお願い」（推測しない・先に一覧を見る）を書き込むのがコツ — AI の動きはコードより言葉で決まる。

作るもの⑤ つなぎ方

ローカル URL でつなぐ ― 設定は 1 行〜1 コマンド

  • 起動はコマンド 1 つ（uvicorn）
  • Claude Code / Cursor は URL + 合鍵ヘッダを書くだけ
  • Claude Desktop 向けには任意で .mcpb
    HTTP 型は直接入らないので、橋渡し（mcp-remote）だけを詰めた小さな拡張を同梱（mcpb/）
ターミナル
$ uvicorn main:app --port 8000

# Claude Code はこれだけ:
$ claude mcp add --transport http employee \
    http://localhost:8000/mcp \
    --header "Authorization: Bearer agent-demo-key"
ライブデモ

この順で見せます

  • uvicorn で起動（localhost:8000）
  • curl で人間フロー: ログイン → 一覧 → 削除も OK
  • curl で AI の合鍵: 一覧は OK → 削除は 403
  • Claude から会話で操作（「社員一覧見せて」→ list_employees）

Claude に「2 番を削除して」と頼むと、削除の道具を持っていないので断ってくる — ここが見せ場。

作ってみて分かったこと

今日の持ち帰り

  • ふつうの API に、AI 対応（受付・リスト・説明）は後付けできる
    既存システムにも同じ手順で足せる
  • AI にさせたくない操作は「リスト外 + 門番」の二段構えで守る
  • 説明文（docstring）が AI の動きを決める — コードより言葉が効く
  • ライブラリの相性に注意
    fastapi-mcp 0.4 は mcp 2.x と非互換 → requirements.txt で 1.x に固定
  • HTTP 型 MCP は .mcpb に直接入らない
    配るなら URL 共有か、橋渡し（mcp-remote）を詰めた .mcpb
